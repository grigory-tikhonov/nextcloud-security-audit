# Аудит безопасности облачного сервиса Nextcloud

## Описание проекта
В рамках выпускной квалификационной работы проведён практический анализ безопасности self-hosted облачного хранилища Nextcloud. 
Развернут лабораторный стенд, выполнены атаки (перехват сессии, подбор пароля, IDOR, загрузка вредоносных файлов, CSRF), 
проанализированы HTTP-заголовки, настроены HTTPS и двухфакторная аутентификация.

## Цели
- Настроить лабораторную среду (VirtualBox + Ubuntu Server).
- Установить и настроить Nextcloud.
- Провести атаки с использованием Burp Suite.
- Устранить найденные уязвимости (HTTPS, 2FA).
- Дать рекомендации по безопасной настройке.

## Используемые технологии и инструменты
- **Виртуализация** — VirtualBox (Ubuntu Server).
- **Исследуемая платформа** — Nextcloud (установка через Snap).
- **Тестирование безопасности** — Burp Suite Community Edition (Proxy, Intruder, Repeater).
- **Подмена cookies** — DevTools (браузер).
- **Двухфакторная аутентификация** — Google Authenticator (TOTP).

## Этапы исследования

### 1. Развертывание лабораторного стенда
- Установка Ubuntu Server в VirtualBox.
- Настройка сети (адаптер Host-Only).
- Установка Nextcloud через Snap.
- Создание тестовых пользователей `user1`, `user2` и загрузка файлов.

### 2. Проведение атак

#### Перехват сессии (Session Hijacking)
- Перехвачен HTTP-запрос аутентификации через Burp Suite.
- В открытом виде передавались логин и пароль.
- Скопированы cookies сессии и подставлены в браузере другого пользователя — доступ получен.
- **Уязвимость:** отсутствие HTTPS.
- **Решение:** включение HTTPS с самоподписанным сертификатом.

#### Подбор пароля (Brute Force)
- Использован модуль Intruder в Burp Suite.
- Словарь из наиболее распространённых паролей.
- Система показала замедление (`X-Nextcloud-Bruteforce-Throttled`) и использовала технологию rate limiting после серии неудачных попыток, однако при слабом пароле подбор возможен.
- **Решение:** включение двухфакторной аутентификации (TOTP) и строгой политики паролей.

#### IDOR (Insecure Direct Object Reference)
- Попытка получить файл другого пользователя через прямой запрос WebDAV.
- Сервер корректно проверил права доступа и отклонил запрос (404 Not Found).
- **Уязвимость не обнаружена.**

#### Загрузка вредоносных файлов (Malicious File Upload)
- Загружены файлы `test.php` и `shell.php.jpg` с PHP-кодом.
- MIME-тип изменён на `image/jpeg` (MIME-spoofing).
- Файлы сохранились, но не выполняются — хранятся вне web-root.
- **Уязвимость не обнаружена.**

#### CSRF (Cross-Site Request Forgery)
- Из запроса загрузки файла удалён заголовок `requesttoken`.
- Сервер вернул `401 Unauthorized` с сообщением «CSRF check not passed».
- **Защита работает корректно.**

### 3. Анализ HTTP-заголовков безопасности
Проверены заголовки:
- `Content-Security-Policy` (CSP)
- `Feature-Policy`
- `X-Content-Type-Options` (nosniff)
- `X-Frame-Options` (SAMEORIGIN)
- `Referrer-Policy` (same-origin)
- Cookies с атрибутами `HttpOnly`, `SameSite=Lax`

**Вывод:** заголовки настроены правильно, но отсутствовал `Secure` на cookies (из-за HTTP).

### 4. Устранение уязвимостей
- **HTTPS:** включён через команду `sudo nextcloud.enable-https self-signed`.
- После включения на cookies добавлен атрибут `Secure`.
- **Двухфакторная аутентификация:** активировано приложение `Two-Factor TOTP Provider`, подключён Google Authenticator для пользователя `user1`.

### 5. Итоговая оценка
После внесённых изменений Nextcloud можно считать безопасным для использования в частной среде при условии:
- обязательного HTTPS,
- включённой 2FA,
- регулярного мониторинга логов,
- соблюдения политики паролей.

## Результаты

| Уязвимость | Была ли | Как устранена |
|------------|---------|---------------|
| Перехват сессии | Да | Включение HTTPS |
| Подбор пароля | Да (при слабом пароле) | 2FA + политика паролей |
| IDOR | Нет | — |
| Загрузка вредоносных файлов | Нет | Изоляция от web-root |
| CSRF | Нет | Встроенный токен |

## Рекомендации
- Всегда включать HTTPS (желательно с валидным сертификатом).
- Настраивать двухфакторную аутентификацию для всех пользователей.
- Использовать сложные пароли и ограничивать число попыток входа.
- Регулярно обновлять Nextcloud и проводить пентесты.
- Проверять HTTP-заголовки безопасности (CSP, HSTS и др.).
